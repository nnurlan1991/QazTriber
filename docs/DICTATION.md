# Диктовка в любом месте (push-to-talk)

> Функция в стиле MacWhisper: удерживаешь горячую клавишу в **любом приложении** —
> речь распознаётся локально и печатается в поле ввода.

## Как работает

Весь runtime живёт в **Rust (Tauri-процесс)**, WebView в записи не участвует
(не троттлится в фоне, работает при скрытом окне):

```
global-hotkey (press/release)
  → cpal: захват микрофона → буфер f32
  → (release) WAV 16-bit (hound)
  → POST http://127.0.0.1:8765/api/dictate (raw body, query: model, expected_language)
  → текст → вставка: enigo (печать / Cmd+V) или arboard (буфер обмена)
```

- **Трей-иконка**: статус (точка ● на macOS при записи), меню «Диктовка вкл/выкл»,
  «Открыть», «Выход». При включённой диктовке закрытие окна прячет приложение в трей.
- **Warmup**: при включении фичи Rust вызывает `/api/dictate/warmup` — модель
  загружается в память заранее (~10 с), первая фраза не ждёт.
- **История**: диктовка НЕ создаёт job и НЕ попадает в историю сессий
  (`/api/dictate` — синхронный, временные файлы удаляются).

## Ограничения и риски

| Что | Детали |
|---|---|
| macOS Accessibility | Печать/вставка (Cmd+V) в чужие приложения требует права в Системные настройки → Конфиденциальность → **Универсальный доступ**. Без него — только режим «В буфер». Frontend показывает предупреждение с кнопкой открытия настроек |
| Фокус | Между отпусканием клавиши и вставкой проходит 2–4 c (распознавание). Если юзер кликнет в другое поле — текст попадёт туда |
| RAM | Пока диктовка включена, модель висит в памяти (220M ~0.9 ГБ, 600M ~2.4 ГБ). Выключение диктовки выгружает модель (если не идёт расшифровка — тогда модель выгрузит сама джоба после завершения) |
| Windows AV | SendInput (эмуляция клавиатуры) иногда триггерит эвристики антивирусов |
| Хоткей | RegisterEventHotKey **поглощает** нажатие системно: выбранная комбинация не дойдёт до других приложений, пока диктовка включена |

## Настройки (localStorage `qaztriber.prefs.v1`)

`dictationEnabled`, `dictationHotkey` (формат JS `e.code`: `alt+shift+KeyD`),
`dictationTrigger` (`hold`/`toggle`), `dictationInsertMode` (`type`/`paste`/`clipboard`).
Модель и язык берутся из настроек приложения (модель — «по умолчанию», язык — `mixed`).

## Ключевые файлы

```
src-tauri/src/dictation.rs   движок: хоткей, захват, WAV, HTTP, вставка, трей-статусы
src-tauri/src/lib.rs         трей, close-to-tray, регистрация команд
backend/app/api/dictation.py POST /api/dictate, /api/dictate/warmup
frontend/src/App.tsx         DictationBridge: prefs ↔ Rust, тосты, синк трея
frontend/src/views/SettingsView.tsx  UI настроек + hotkey-recorder + Accessibility
```

## Ручная проверка (macOS)

1. Настройки → Диктовка → Вкл → появился трей-пункт «Диктовка: включена».
2. Держать Alt+Shift+D в заметках/браузере, говорить, отпустить → текст напечатан.
3. Первое включение печати — выдать право Accessibility, повторить.
4. Скрыть окно (закрыть) → хоткей продолжает работать; из трея «Открыть» возвращает окно.
5. Поставить режим «В буфер» → после фразы текст в буфере.
6. Режим «Переключение»: нажал — запись, нажал ещё раз — стоп и вставка.

## Ручная проверка (Windows)

То же самое; Accessibility не нужен. Проверить, что антивирус не ругается на эмуляцию ввода.
